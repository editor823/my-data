검색량은 나오는데 문서수는 조회 실패? API 오류 확인 순서

🏷️ 콘텐츠 가이드 🔍 키워드 조사

검색량이 보이는데 블로그 문서수가 ‘조회 실패’라면 문서가 0개라는 뜻이 아닙니다. 서로 다른 데이터 요청 중 일부가 실패했을 가능성을 먼저 확인해야 합니다. 모든 API 키를 무작정 다시 발급하기 전에 어떤 항목에서 오류가 났는지 나누어 보세요.

실제 오류 화면에서 출발하기

2026년 9월 20일 점검 당시 한 화면에 ‘블로그 문서수 API HTTP 401 / Authentication Failed’와 ‘검색광고 API HTTP 429’가 함께 표시된 사례가 있었습니다. 전자는 인증 확인이 필요한 응답이고, 후자는 요청 제한을 확인해야 하는 응답입니다. 두 오류가 동시에 나타났다고 원인이 하나라고 단정하지 않았습니다.

화면의 증상먼저 확인할 것하지 말아야 할 해석
검색량은 표시, 문서수는 실패블로그 검색용 인증정보와 이용 API 설정문서수 0개로 계산
401 Authentication FailedClient ID·Secret의 짝, 누락·공백, 발급받은 서비스도메인 이전 때문에 무조건 키가 무효라고 단정
429 요청 제한어느 제공처의 응답인지, 사용량·반복 요청 상황계속 새로고침하면 해결된다고 판단
관심도만 비어 있음DataLab 이용 설정과 해당 검색어의 응답 유무검색 수요가 없다고 확정

검색광고 키와 검색 API 키는 역할이 다릅니다

사이트의 월 검색량 조회와 블로그 문서 검색은 같은 숫자를 가져오는 요청이 아닙니다. 설정 화면에서 각 입력란의 이름을 확인하고, 검색광고용 값을 검색 API의 Client ID·Secret 입력란에 넣지 않았는지 살펴보세요. 발급 화면에서 복사할 때 값 앞뒤의 공백이나 일부 누락도 확인합니다. 키 원문을 문의 게시판이나 채팅에 붙여넣지는 마세요.

다섯 단계로 범위를 좁혀 보세요

  1. 오류가 난 항목을 기록합니다. 검색어, 발생 시각, 검색량·문서수·관심도 중 실패한 항목을 메모합니다.
  2. ‘내 API 키 설정’을 확인합니다. 본인의 발급 화면과 입력란 종류가 맞는지 직접 대조합니다.
  3. 서비스 이용 설정을 확인합니다. 블로그 검색은 검색 API, 관심도는 DataLab 관련 설정을 확인합니다. 실제 발급 관리 화면의 명칭이 바뀌면 해당 공식 안내를 따릅니다.
  4. 한 검색어로 확인합니다. 설정을 바로잡은 뒤 단건 조회를 먼저 합니다. 여러 탭에서 대량 요청을 동시에 반복하지 않습니다.
  5. 429라면 반복 호출을 멈춥니다. 제공처의 사용량·제한 안내를 확인하고 안내된 조건에 따라 재시도합니다. 모든 제공처가 한국시간 오전 9시에 초기화되는 것은 아닙니다.

정상 조회를 확인한 범위

이후 유효한 개인 키가 저장된 브라우저의 점검에서는 ‘청년미래적금’ 단건 조회와 연관 키워드 10개 조회에서 검색량·블로그 문서수가 반환됐고, 당시 두 오류 안내는 나타나지 않았습니다. 이것은 해당 시점의 동작 확인이며 모든 사용자 환경의 인증 문제나 향후 요청 제한이 사라졌다는 보장은 아닙니다.
