키워드 하나를 글쓰기 요청서로 바꾸는 6칸 작업표

🏷️ 콘텐츠 가이드 🔍 AI 글쓰기

‘연말정산 글 써 줘’처럼 키워드만 넣으면 어떤 사람의 어떤 문제를 해결할지 정해지지 않습니다. 도구나 모델을 바꾸기 전에 짧은 글쓰기 요청서를 만들어 보세요. 제목을 길게 만드는 작업이 아니라, 글이 다룰 질문과 확인한 자료를 정하는 작업입니다.

먼저 채울 여섯 칸

항목적을 내용확인 질문
독자지금 이 정보를 필요로 하는 사람초보자와 경험자가 같은 설명을 필요로 하나?
핵심 질문글 한 편이 해결할 문제 하나읽은 뒤 무엇을 할 수 있어야 하나?
근거직접 확인한 자료와 확인 날짜링크를 실제로 열고 주장을 대조했나?
범위다루는 것과 다루지 않는 것확인하지 않은 조건까지 약속하나?
목차독자의 행동 순서준비물보다 실행부터 설명하지 않나?
완료 기준독자가 끝에 얻을 결과정보를 다시 검색해야만 진행할 수 있나?

작성 예시: 이미지 형식을 고르는 독자

이 사이트에서 실제 변환 시험에 사용한 그림을 소재로 작업표를 작성했습니다. 아래 수치는 2026년 9월 20일 내려받은 파일 기준입니다. 이 예시는 글을 기획한 기록이며 AI 모델별 성능을 비교한 실험이 아닙니다.

  • 독자: 글에 넣을 안내 이미지를 가볍게 만들고 싶은 블로그 초보자.
  • 질문: PNG를 JPG로 바꾸면 반드시 작아지는가?
  • 근거: 같은 1,200×800 그림의 PNG 21,439바이트, WebP 85% 16,236바이트, JPG 85% 48,268바이트.
  • 범위: 이 시험 파일의 용량만 비교. 사진 전체의 화질·속도·검색 순위는 결론 내리지 않음.
  • 목차: 시험 조건 → 결과 표 → JPG가 더 큰 사례의 의미 → 자신의 파일로 재현하는 순서.
  • 완료 기준: 독자가 동일한 원본으로 두 형식을 비교하고, 용량만으로 품질을 판단하지 않도록 안내.

‘이미지 압축 꿀팁’이라는 넓은 요청보다 자료와 결론의 한계가 뚜렷해집니다. 원본과 변환 결과가 있는 실제 비교 가이드에서 근거 파일을 확인할 수 있습니다.

복사해 채우는 요청문

전체 키워드: [입력]
독자와 상황: [입력]
해결할 질문 하나: [입력]
확인한 자료·링크·확인일: [입력]
아직 확인하지 못한 내용: [입력]
원하는 순서: 상황 설명 → 근거 → 절차 → 예외 → 다음 행동
조건: 제공하지 않은 수치·경험·인용을 만들지 말 것. 자료가 부족한 부분은 확인할 질문으로 표시할 것. 초안 끝에 추가 확인 목록을 붙일 것.

이 요청을 붙였다고 모든 생성 결과가 조건을 지키는 것은 아닙니다. 근거가 없는 문장을 출력에서 다시 찾아야 합니다. 개인정보나 API 키를 근거 자료 칸에 넣지 않습니다.

사이트의 프롬프트를 고를 때

  1. 검색용 안내, 채널용 요약 등 글의 목적을 먼저 정합니다.
  2. 글쓰기 프롬프트에서 목적에 맞는 항목을 선택합니다.
  3. 위 작업표와 필요한 공개 자료만 함께 전달합니다.
  4. 제목에 키워드가 들어갔는지보다 핵심 질문에 실제 답했는지 확인합니다.
  5. 초안 검토 순서에 따라 숫자·날짜·경험 표현을 검토합니다.

자료가 비었을 때는 글부터 늘리지 마세요

근거 칸을 채우지 못한다면 원문 조사나 직접 시험을 먼저 합니다. ‘자세하게 3,000자’ 같은 분량 요구만 추가하면 같은 설명이 반복될 수 있습니다. 목표는 긴 출력이 아니라 독자에게 필요한 근거와 행동을 갖춘 초안입니다.
